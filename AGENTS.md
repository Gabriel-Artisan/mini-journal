# Project Engineering Guidelines

This is a small but real web application. Build it as a usable, finished product with professional engineering standards.

## Working Approach

- Inspect the existing project and relevant code before making changes.
- Make incremental, reviewable changes. Avoid unrelated edits and unnecessary refactors.
- Prefer simple, maintainable solutions; add dependencies only when they provide clear value.
- Preserve existing functionality when modifying the project.
- Write clear, maintainable code and include appropriate tests for implemented functionality.
- Run relevant tests, checks, and verification after changes.
- Consider accessibility, responsive behavior, usability, and basic security in all user-facing work.
- Keep documentation current when behavior or project structure changes.
- Use Git with small, focused commits at meaningful checkpoints. Never commit secrets, credentials, or sensitive data.

## Decisions and Significant Changes

The human developer makes product decisions and approves significant changes. Codex assists with planning, implementation, testing, and verification.

When a task is ambiguous or could significantly affect architecture or product behavior, explain the issue and propose a plan before implementing it.
